🔴 v0.6 초판(2026-08-15 오전)의 오류 — 같은 날 정정: 초판은 발경 키를 «ZXCV → QWAS»로 바꿨는데 그것이 틀렸다. Q·W·A·S는 키가 아니라 enum SkillKey의 식별자 이름이다. Doors.InputHint가 정본이며 플레이어 입력은 1·2·3·Shift다. «문서 ZXCV vs 코드 QWAS»는 층위가 다른 둘을 맞세운 오진이었다 — PROJECT_LOG L51이 이미 그렇게 경고해 두었는데 놓쳤다.
✅ 조작 체계를 코드에서 재추출: 패턴은 마우스·터치로 긋고, 계열은 1 검 · 2 권 · 3 장 · Shift 보로 고른다(Doors.InputHint). v0.5의 ZXCV 발경 배치는 폐기됐고, QWAS도 키가 아니다. 문서에서 둘 다 키로 쓰지 않는다.
✅ 28초식 → 44초식: 7패턴 → 11패턴 × 4계열. 추가 4패턴 ㄱ N ㄷ ◇. §9.2 매트릭스를 Skills.csv(44행)에서 다시 뽑았고 Tier 수치표를 추가했다.
✅ 문(門) 선택 조작 명문화: 1 2 3 Shift — v0.5에 아예 기재가 없었다.
✅ §9.4 파훼(破) 상성 체계 신설: 적도 초식을 쓴다. 4순환 상성 + 판정 3수치 + 전조 시간 + 등급별 배분. v0.5 이후 구현·확정된 것이 문서에 한 줄도 없었다.

一. 한 줄 컨셉

"한지 위에 붓으로 글을 쓰듯 무공의 패턴을 그리고, 계열을 골라 발경(發勁)하여 무협 초식을 펼치는 3D 셀룩 액션 RPG. 황제의 막내 황자가 무극지체를 비밀로 한 채 무림에 잠입해, 황실과 강호 양측의 그림자를 헤쳐 나간다. 보스 처치 시 동물 영혼을 봉인해 신의 권능을 얻는다."

二. 세계관 (7대 분류 트리)

중원 무림 + 황실 + 새외. 100년 전 오대천왕의 난으로 다극화. 무공은 외공·내공·심공.

분류대표 세력특징
① 정파무림맹(구파일방 10) + 오대세가(남궁·모용·당가·진가·황보)협을 표방, 내부 권력투쟁
② 사파음마곡·흑사방·녹림독·암살·청부
③ 마교혈천교·백련교·천마신교흡정·강시·광신
④ 새외북해문·남만독곡·서장밀종·동영빙공·고독·금강기·검술
⑤ 황궁금의위·동창서창·어림군황실 직속, 주인공의 출신
⑥ 상단만금상단·천하상단·표국중원 경제·정보망
⑦ 하오문·중립하오문·의가·은둔자정보·치료·변수

三. 주인공 · 황자 서사 (v0.4 유지)

이천린(李天隣) 14황자 + 혼원무극지체 · 본인·황제·진공공·제갈무영 4명만 신분 인지 · 신분 노출도 0~100 변수.

그림자 추적: 적대(혈천교 흑영대 / 황후파 / 동창 / 음마곡) + 보호(진공공 / 금의위 / 제갈무영).

상세는 v0.4 §2.5 또는 WuxiaPatternAction_Story.html 참조.

四. 신물 · 봉신 시스템 (v0.4 유지)

26세력 보스 처치 → 동물 영혼 봉인 → 신물 획득. 메인 1 + 서브 2 = 최대 3개 동시 장착. 무극지체 시너지로 주인공만 3개 가능.

왼손 (계열 선택 · 보조):

   ┌───────┐ ┌───┐ ┌───┐      Shift = 보(步) ← SkillKey.S
   │ Shift │ │ F │ │Spc│      R = 신물 메인 / Shift+R = 서브

        — 패턴 시작 시 시간 0.3배, 이동·회전 자동 정지

⚠ 계열 선택은 키보드 4개가 아니라 1·2·3·Shift 넷이다. SkillKey.Q/W/A/S는 그 계열을 데이터에서 부르는 이름일 뿐, 눌러야 하는 키가 아니다. 이 둘을 같은 줄에 나란히 적어 두는 이유가 그것이다 — 떼어 놓으면 또 섞인다.

8.3 모바일 가로 화면

  • 좌하단: 패턴 입력 영역 (한지 패널) — 엄지로 붓 그리듯
  • 우하단: 계열 4 버튼 — 큰 한자(劍/拳/掌/步)로 표시. 모바일은 탭이므로 PC의 1·2·3·Shift에 대응
  • 우상단: 신물 슬롯 3개 (탭으로 발동)

8.4 입력 우선순위 + 슬로우모션

1. 패턴 입력 중 (마우스 드래그) → Time.timeScale = 0.3
   · 이동·회전 자동 정지
   · 계열 선택 입력 무시
   · "기를 모아 패턴을 발하는 순간" — 무협 시간 압축 연출
2. 패턴 완료 → Time.timeScale = 1.0 + 1.5초 윈도우 시작
   · 윈도우 안 계열 선택(1/2/3/Shift) = 매칭된 초식 발동
3. 윈도우 종료 후 → 계열 키 = 기본 행동 (1=약공, 2=차지강공, 3=장풍, Shift=회피대시)
4. 주화입마 상태 → 1초 경직, 입력 불가

패턴 윈도우(초식 입력 유예): 1.5초 (2026-06-11 확정)

8.5 키 변경 옵션 (설정)

PC 사용자는 설정 메뉴에서 리바인딩 가능. 기본값 1 · 2 · 3 · Shift, 대체안 다음 제공:

  • ZXCV 변형: 검→Z, 권→X, 장→C, 보→V v0.5 기본값이었던 배치
  • 마우스 확장: 좌클릭=검, 우클릭=권, 휠클릭=장, Shift=보
  • JKLI 변형: 오른손 사용자용
⚠ 리바인딩은 표시 계층만 바꾼다. 어떤 배치를 고르든 데이터가 부르는 이름은 SkillKey.Q/W/A/S 그대로다 — 그건 키가 아니라 계열 식별자이기 때문이다. TC·버그 리포트에 조작을 적을 땐 실제 입력(1·2·3·Shift)을 쓰고, 데이터를 가리킬 땐 식별자를 쓴다. 섞어 쓰면 v0.6 초판과 같은 오진이 난다.

9.4 파훼(破) 상성 체계 v0.6 신설

⚠ v0.5에 이 절이 통째로 없었다. 적도 초식을 쓰고 플레이어가 그것을 파훼한다는 구조가 2026-08-12에 구현·확정됐는데 기획서에는 한 줄도 반영되지 않았다. 이번 개정의 핵심이다.

9.4.1 4순환 상성

步 → 劍 → 拳 → 掌 → 步        (화살표 = "깬다")

각 문은 정확히 하나를 깨고 하나에게 깨진다. 외울 것이 16개가 아니라 4개다. 각 관계에는 한 줄짜리 이유를 데이터로 붙인다(Doors.BreakReason) — 이유 없는 상성표는 매번 표를 다시 봐야 한다.

파훼이유 (BreakReason)계열 색 (Tint)
步가 劍을칼은 닿아야 벤다. 그림자는 못 벤다어두운 녹빛
劍이 拳을주먹이 닿기 전에 칼끝이 먼저 닿는다밝은 청백
拳이 掌을장력은 피하는 게 아니라 뚫는 것붉음
掌이 步를장력은 면(面)이다. 물러설 자리가 없다금빛

색약 대비로 색상만이 아니라 명도까지 벌린다 — 청백 > 붉음 > 금빛 > 어두운 녹빛. 새 어휘를 만들지 않았다: 플레이어는 이미 123Shift로 문을 고르므로 파훼는 이미 아는 조작이다.

9.4.2 판정 3수치 (FormClash.cs 상수)

대응상수값결과
맞는 문ClashResult.Broken → ScaleDamage0f破 — 피해 0 + 경직 1.6초(BreakStunSeconds) + 되받는 피해 2배(BreakCounterScale)
틀린 문WrongDoorDamageScale0.6f피해 60% — 맞았지만 그냥 서 있던 것보다는 낫다
무대응—1.0정타
가운데 칸이 이 표의 전부다. 오답을 정타와 같게 두면 아무도 시도하지 않고, 시도가 없으면 상성을 배울 기회 자체가 없다. 오답이라고 판정 창을 닫지도 않는다 — 전조가 남아 있으면 다시 낼 수 있다.

9.4.3 전조(텔레그래프) 시간

일반 초식 0.80 ~ 1.50초(평균 1.14) · 절초 2.40초(일반의 약 2배). 절초는 FinisherIntervalSeconds = 22f — 22초에 한 번, 3페이즈에서만, 위력 FinisherRatio = 2.2f.

전조 길이는 난이도 손잡이다. 0.5초로 죽이면 "못 봤다"고 하고, 2.4초를 주면 "알고도 못 했다"고 한다. 뒤쪽만이 다음 판에 다르게 하게 만든다. ⚠ 따라서 전조 값은 런타임에 조정 가능해야 한다.

9.4.4 등급별 배분 — 드물어야 무공이다

등급무공왜
卒 잡졸없음징집병. 칼은 들었지만 배운 적이 없다
兵 무사없음훈련은 받았으나 초식은 없다
將 두목서명초식 1종 (ChampionForms 3종 중)개체마다 고정 — instanceID로 뽑는다. 난수 금지(매번 다르면 학습 불가)
보스페이즈별 세트 + 절초문파 고수. 예: 흑사채주 7초식 + 절초 「사왕단혼」

표시 규칙 — 보스전은 표찰(읽을 여유가 있다), 전장은 몸이 계열 색으로 빛난다(읽을 게 없고 보면 안다). 표찰 HUD는 자리가 비었을 때만 곁들인다(ShowForm(form, force:false)).

9.4.5 아직 안 정한 것

  • 전조 창 불일치 (미수정) — BossCounter.OpenCounterWindow가 창 종료 시각을 시작 때 한 번 계산한다. 전조를 진행 중에 늘리면 반격 창만 먼저 닫힌다. 재개 조건: 전조 길이를 실시간 조정하며 밸런싱하는 작업이 실제로 생길 때.
  • 오답 60%의 근거 — "정타와 달라야 한다"만 있고 60인지 40인지 잰 적이 없다
  • 44초식의 계열 배분 — 현재 11패턴 × 4로 균등하나, 계열별 개수를 다르게 갈지 미정
  • 26신물과 계열의 관계 — 신물이 계열을 바꾸는가, 계열 안에서 강화하는가
