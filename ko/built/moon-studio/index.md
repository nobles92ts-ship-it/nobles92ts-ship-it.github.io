**문스튜디오는 제가 방향을 정하고 AI와 함께 게임을 만드는 1인 스튜디오입니다.** 지금의 만드는 법은 v3입니다. 기능 하나를 여러 직군에 넘기는 대신, 오너 한 명이 끝까지 만들고 다른 에이전트가 결과를 검증합니다.

**개선의 중심은 세션을 더 켜는 것보다, 나눈 일이 빠지거나 겹치지 않게 하는 것입니다.** 아트는 독립 세션으로 맥락을 이어가고, 개발은 카드별 오너, 판정은 새 검증관에게 맡깁니다. 개발·QA 상시 조율자는 실제 병목을 확인한 뒤 하나씩 추가합니다.

2026-10-19에 공유 운영 규칙과 로컬 가드를 설치했습니다. 격리 시험 30개는 통과했지만, 진행 중 게임의 새 방식 전환과 실제 세션 간 전달 시험은 아직 확인하지 않았습니다.

> **[도판]** 기존 v3의 역할 구성을 유지하고 인수·현재판·자원 예약을 보강했다. 개발·QA 상시 세션을 기본으로 더하지 않는다.
>
> 문스튜디오의 기본 혼합 구조. 게임당 디렉터 하나가 배정·현재 보드·통합·완료를 책임진다. 카드별 오너가 구현하고 새 검증관이 통합판을 판정한다. 아트01·02는 지속 독립 세션으로 납품한다. 추가 개발·QA 조율자는 병목 확인 뒤 시범한다. 규칙·가드 설치와 실제 게임 전환은 구분한다.

## 저는 원하는 것을 말하고 디렉터가 일을 나눕니다

예를 들어 「전투가 더 잘 보이게」라는 요청을 주면, 디렉터가 코드를 읽고 화면에서 확인할 변화로 나눕니다. 카드마다 고칠 범위와 합격 조건을 적습니다. 오너는 그 카드의 설계 세부, 코드, 데이터와 시험을 함께 맡습니다.

**디렉터는 게임당 메인 세션 하나입니다.** Claude나 Codex가 이 자리를 맡아도 보드와 카드로 이어받습니다. 제가 여러 세션 사이에서 말을 복사해 나를 필요가 없게 만드는 것이 목표입니다.

## 만드는 눈과 판정하는 눈을 나눕니다

오너가 시험을 통과했다고 끝내지 않습니다. 디렉터가 작업을 합친 뒤, 별도 검증관이 그 판을 켜 보고 깨뜨려 봅니다. 못 돌린 것은 이유와 함께 남깁니다.

그림도 같은 원칙입니다. 깨알에는 캐릭터·동작을 맡는 아트01과 기술·이펙트·연출을 맡는 아트02가 있고, 결과를 게임에 넣는 일은 디렉터가 맡습니다. **그림 파일이 있다는 것과 게임에서 잘 보인다는 것은 다른 확인입니다.**

## 전체 흐름은 디렉터가 책임집니다

세션을 나누면 「누가 받았나」와 「정말 끝났나」가 중요해집니다. 그 사이를 제가 중계하지 않도록 역할을 정합니다.

| 역할 | 맡는 책임 | 내는 결과 |
|---|---|---|
| **디렉터** | 배정·수신·진행을 추적하고 충돌을 조정 | 검증 결과에 근거한 보드 상태 확정 |
| **오너** | 자기 범위를 확인하고 작업·막힘을 보고 | 작업한 판과 결과·증거 제출 |
| **검증관** | 합격 조건을 독립적으로 확인 | 통과·실패·미실행 판정과 근거 |

**오너의 「완료했습니다」는 제출입니다.** 검증관의 확인을 거쳐 디렉터가 완료 상태를 확정합니다. 디렉터가 자기 판단으로 검증 실패를 통과로 바꾸는 구조는 아닙니다.

## 세션을 나눌수록 전달을 추적합니다

새 로컬 가드는 작업 예약·수신·결과의 기록과 등록된 자원 충돌을 검사합니다. 실제 전달은 기존 서브에이전트·아트 전달·브리지를 씁니다. 수신이 없으면 디렉터가 기존 실행을 조회하고 같은 요청을 재알림합니다. 자동 감시·재알림 서비스까지 만든 것은 아닙니다.

> **[도판]** 가드의 submit은 결과 제출, finish는 실제 종료 확인 뒤 자원 반환이다. 통합판의 별도 검증을 거쳐 디렉터가 보드를 닫는다.
>
> 업무 흐름은 예약 후 전달, 수신, 작업, 제출, 별도 검증, 보드 완료다. 중복 예약이면 기존 실행을 조회한다. 제출 뒤 실제 실행 종료를 확인해 자원을 반환하는 finish는 제품 통과가 아니다. 검증 실패는 수정으로 돌아가고 공개 배포는 별도 승인이다.

가드는 같은 PC에서 같은 로컬 상태를 쓰는 참여자 사이에 적용됩니다. 등록하지 않은 실행이나 다른 PC의 작업까지 막아 주지는 않습니다. 기존 게임 실행기와 화면 잠금도 계속 필요합니다.

## 여기부터는 자세한 기록입니다

## 추가 세션은 병목이 확인된 역할부터 연다

처음 공개한 개선안은 개발·QA 지속 담당을 함께 두는 방향이었다. 적대적 리뷰에서는 이미 기능 오너·새 검증관·독립 아트를 쓰고 있다는 점이 드러났다. 여기에 조율자를 늘리면 디렉터와 같은 설명·진행 관리를 반복할 수 있어 기본 구성을 유지했다.

개발 의존성 정리나 QA 이력 재구성이 실제 병목이면 해당 역할 하나만 시범한다. 먼저 디렉터가 그만 반복할 업무를 정한다. 조율자는 상태와 근거를 이어 주며, 새 통합판을 검사하는 검증관의 판단을 대신하지 않는다.

아트01·02는 오래 이어지는 제작 맥락 때문에 독립 세션을 유지한다. 짧은 조사나 기존 결과 조회로 끝날 일까지 지속 세션으로 만들지는 않는다.

## 책임과 상태를 함께 고정한다

디렉터는 담당 배정, 수신·진행 추적, 누락 재요청, 작업 충돌 조정과 보드 상태 확정을 책임진다. **보드의 쓰는 사람은 하나**다. 최상단의 최신 인수 선언·현재 카드·기준판부터 읽고, 과거 이력의 옛 디렉터 선언으로 권한을 되찾지 않는다.

오너는 수신·범위 확인 뒤 작업하거나 막힌 이유를 보고한다. 결과에는 어떤 판을 바꿨고 무엇을 확인했는지 남긴다. 검증관은 그 결과를 승인된 조건에 대조하고, 디렉터는 판정과 남은 조건을 읽어 완료 여부를 기록한다.

안전한 묶음 경계에서 옛 보드 이력을 접고 현재 요약과 원문 링크를 남기도록 양식을 바꿨다. 진행 중인 게임 보드를 이 작업에서 대신 정리하지는 않았다. 취향·밸런스 적용·공개 배포의 결정은 제가 맡는다.

## 전달 누락과 중복 실행을 함께 막는다

카드마다 식별자·요청 판·시도·담당·디렉터 인수 세대와 소스·자산·합격 조건 지문을 고정한다. 수정 영역과 고유 결과 경로도 쓰기 전에 예약한다. 예약 결과가 새 실행을 허용한 경우에만 작업자를 한 번 호출한다. 기존 예약이면 조회하거나 이어받는다.

**재알림은 새 작업 실행 명령이 아니다.** 종료 여부를 모르면 새 시도나 별도 상태 저장소로 우회하지 않는다. 취소 요청만으로 자원을 풀지 않고 실제 종료를 확인한다. 완료된 시도의 영수증을 남겨 늦은 결과와 결과 경로 재사용도 구분한다.

지문 대조는 계약 봉투가 같은지를 확인한다. 실제 소스·자산·합격 조건 원문이 맞는지, 결과가 사실인지, 검증관이 구현자와 다른지는 따로 확인해야 한다. 가드는 OS 권한이나 직접 파일 쓰기를 통제하는 보안 경계가 아니다.

## 자원 상한은 세션 수와 별도로 합산한다

기능 오너는 같은 프로젝트의 모든 세션을 합쳐 최대 4명이다. Unity 코드 작업은 같은 PC에 등록된 프로젝트 전체에서 1개다. 화면 검사·긴 CPU 시험·성능 측정·일괄 렌더도 같은 로컬 상태에서 점유와 충돌을 검사한다.

화면 검사는 CPU 시험·성능 측정·렌더와 겹치지 않게 한다. 성능 측정은 다른 무거운 작업과 분리한다. CPU 시험과 렌더의 각 1개 상한은 보수적인 운영 선택이며, 측정한 최적값은 아니다. 중첩 작업자나 높은 노력 설정도 이 상한의 예외로 두지 않는다.

## 설치 검증과 게임 전환은 다른 결과다

공유 규칙·역할 정의·양식·가드·Codex 진입점을 합쳐 기존 12개 파일을 고치고 5개를 추가했다. 가짜 프로젝트와 격리 상태 저장소에서 가드 시험 **30개 통과**, 문장·분기 통합 커버리지 <strong>89.07%</strong>를 확인했다. 호출 지침도 격리 환경에서 CLI 17회와 33개 assertion으로 확인했다.

이 수치는 실제 세션 전송이나 게임 품질의 측정값이 아니다. 진행 중 게임의 현 디렉터에게 새 규칙을 읽고 안전한 묶음 경계에서 새 카드부터 도입하도록 인수 요청을 남겼다. 실제 인수·전환은 미확인이고, 정상 전달·누락·중복·재개 등을 확인할 통신 경로 시험 10개도 미실행이다. 이번 변경으로 게임 회귀 시험을 다시 돌리지는 않았다.

## 분리의 이점은 총비용과 놓친 결함으로 확인한다

분리하면 각 담당이 자기 맥락을 유지하고 디렉터에게 긴 실행 로그가 쌓이는 일을 줄일 수 있다. 전체 토큰은 별개다. 공통 자료를 다시 읽고 결과를 전달·검토하는 비용이 있으므로, 세션 수가 늘었다고 총토큰이 줄었다고 말할 수 없다.

다음 두 묶음에서는 사람·자원 대기를 나눈 완료 시간, 재작업, 검증 뒤 발견한 결함, 수신 누락·중복 실행과 디렉터의 재설명을 기록한다. 사용량은 디렉터·작업자·조율·재시도를 합쳐 수집 가능한 범위만 비교한다. 빠진 사용량이 있으면 토큰 우위는 미판정이다. 이는 앞으로의 측정 계획이다.

## v3는 직군 사이 전달보다 기능의 책임을 묶는다

2026-10-08에 제작 구조를 바꿨다. 예전에는 기획·개발·QA가 다른 세션에서 문서와 메시지를 넘겼다. 현행 v3의 기본 단위는 **게임당 디렉터 하나, 카드당 기능 오너 하나, 만든 쪽과 다른 검증관**이다. 10월 19일의 보강은 이 구성의 인수·중복·자원 관리를 강화했다.

| 구분 | 이전 방식 | v3 |
|---|---|---|
| 작업을 나누는 기준 | 직군과 세션 | 화면에서 확인할 기능 하나 |
| 진행을 찾는 곳 | 세션별 메시지·전달 문서 | 현재 보드와 카드·결과·검증 기록 |
| 기능의 담당 범위 | 기획·코드·그림을 직군 사이에 전달 | 오너가 카드 안의 설계 세부·코드·데이터·창 없는 시험을 맡음 |

디렉터는 카드가 같은 파일·함수를 건드리는지 먼저 본다. 겹치면 합치거나 순서를 정한다. 독립된 작업은 나눌 수 있지만 Unity 코드 작업과 화면을 쓰는 시험은 자원을 공유하므로 동시에 밀어 넣지 않는다.

## 창 없는 시험은 만들면서 하고 화면 시험은 합친 뒤 한다

오너는 구현 중에 창 없는 시험을 작성하고 돌린다. 화면 검증은 묶음 끝에 검증관이 통합한 판에서 맡는다. 첫 검증·마일스톤·실행 파일을 구운 뒤에는 넓게 보고, 고친 뒤 재검증은 바뀐 곳과 앞서 실패한 조건을 중심으로 좁힌다.

**제품 결함, 검사 도구의 문제, 알려진 문제, 미실행을 같은 실패 수로 합치지 않는다.** 검증관은 재현과 판정을 남기고 코드를 직접 고치지 않는다. 수정은 해당 오너에게 돌아간다.

실행 파일을 만든 뒤에도 그 파일을 다시 확인한다. 저장소의 코드가 맞는 것만으로 받은 파일의 동작을 보증할 수 없기 때문이다.

## 아트는 오래 붙들되 게임에 넣는 책임은 한곳에 둔다

깨알의 아트01은 캐릭터 애니메이션·동작과 경기장 그림을, 아트02는 기술·이펙트·연출 그림을 맡는다. 처음 하는 종류는 작은 시범을 보고 방향을 정한 뒤 넓힌다. 결과는 임시 납품 위치까지 만들고, 디렉터가 검증할 판에 넣는다.

2026-10-16 이후에는 일감에 따라 Claude가 초안을 잡고 Codex가 본작업과 마무리를 맡는 분담도 쓴다. 가벼운 일은 한쪽이 끝낼 수 있다. **도구 이름보다 납품물과 검수 책임이 먼저다.** 취향과 완성도에 대한 마지막 결정은 제가 한다.

## 만드는 버전과 받는 버전은 다르다

깨알의 공개 받기 저장소는 2026-10-26부터 v0.2.2를 최신 배포판으로 가리킨다. 2026-10-24에는 v0.2.1, 2026-10-23에는 v0.2.0, 그 전까지는 v0.1.6이었고, 로컬 보드에는 v0.1.7 빌드와 v0.2.0 시험판의 제작·검증이 별도로 남아 있었다. 새 기능의 코드나 시험판이 있다는 이유로 받기 버튼의 번호를 올리지 않았다.

밸런스 적용과 공개 배포도 별도 결정이다. 제작 절차의 마지막에는 사람의 배포 승인이 있으며, 로컬 빌드 완료를 자동 공개로 처리하지 않는다.

## 문서의 칸은 역할 조직도가 아니다

게임별 주소 밑의 설계·기획·세계·구현·아트·검증은 **읽는 사람을 위한 기록 분류**다. 그 칸마다 별도의 상시 세션이 있다는 뜻은 아니다. 무협 Unity 원형의 글은 그 당시의 수치와 교훈으로 보존한다.

[미래 게임 1](/ko/built/moon-studio/future-1/index.md)과 [미래 게임 2](/ko/built/moon-studio/future-2/index.md)는 다음 작업을 생각하는 빈 문서 자리다. 실제 게임 수나 진행 중인 프로젝트로 세지 않는다. 타워 디펜스·물 흐름 퍼즐·입문 강좌도 출시 중인 게임과 섞지 않고 실험·학습 기록으로 둔다.

## 구조를 바꾼 것과 빨라졌음을 증명한 것은 다르다

v3의 목표는 전달 비용과 사람의 중계를 줄이는 것이다. 이번 갱신은 운영 규칙·가드의 설치와 격리 검증을 기록한다. 실제 게임에서의 도입 효과, 총토큰 절감, 완성도 우위는 아직 측정하지 않았다.

문스튜디오는 제가 만든 것을 공개적으로 깨뜨려 볼 수 있는 실험대이기도 하다. 구현한 것, 검증한 것, 아직 못 한 것을 나눠 적어야 그 실험이 다음 작업에 쓸 수 있는 기록으로 남는다.
