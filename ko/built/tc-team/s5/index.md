**수정 계획을 실제로 적용하고, 검문 넷을 통과시킵니다. «거부가 정상 동작»인 단계입니다.**

## 「거부가 정상 동작」이 무슨 뜻인가

이 단계의 성격을 정하는 한 줄입니다.

수정 계획에는 <strong>「이 행이 지금 이렇게 되어 있다」</strong>는 현재 값이 같이 옵니다. 그리고 적용할 때 **그 값이 맞는지 먼저 확인**합니다.

**안 맞으면 적용하지 않고 거부합니다.**

| 상황 | 동작 |
|---|---|
| 현재 값이 계획과 같음 | 고침 |
| **현재 값이 다름** | **안 고치고 거부** |

왜 이게 중요하냐면 — **계획을 세운 시점과 적용하는 시점 사이에 내용이 바뀌었을 수** 있습니다. 그러면 **엉뚱한 것을 고칩니다.**

예를 들어 「7번 행의 「실패한다」를 「실패 메시지가 뜬다」로」라는 계획이 있는데, 그 사이에 행이 밀려서 **7번이 다른 케이스**가 됐다면 — 그대로 적용하면 **멀쩡한 케이스를 망칩니다.**

그래서 **거부는 고장이 아니라 안전장치**입니다. 거부가 나오면 **수정 계획을 다시 만듭니다.**

## 검문 넷이 각각 다른 것을 봅니다

| 검문 | 보는 것 | 걸리면 |
|---|---|---|
| **표현** | 두루뭉술한 말, **근거 없이 남에게 미루는 표현** | 고쳐서 다시 |
| **중복** | **기대 결과가 완전히 같은** 행 | 합치거나 차이를 명시 |
| **누락** | 장부에서 **안 챙겨진 규칙** | 행을 새로 만들어 채우고 다시 |
| **분류** | 같은 분류가 **떨어져 앉음** | 자동으로 모음 |

## 중복 검문이 「완전 동일만」 막는 이유

이게 좋은 판단이었습니다.

중복 검문은 **완전히 똑같은 것만** 막고 **비슷한 것은 안 막습니다.**

왜냐면 — **코드가 「비슷함」으로 자르기 시작하면 정당하게 비슷한 케이스까지 죽습니다.**

예를 들어 이 둘은 비슷합니다.

- 「재료가 **1개** 부족하면 실패한다」
- 「재료가 **전혀 없으면** 실패한다」

기계가 보면 거의 같은 문장입니다. 그런데 **둘 다 확인해야 하는 다른 경우**입니다. 경계값과 0은 다르게 깨질 수 있습니다.

그래서 **「비슷함」 판정은 앞 단계 AI가 맡고, 코드는 「완전히 같은 것」만** 봅니다.

> **기계가 판단할 수 있는 것과 판단하면 안 되는 것을 갈라야 합니다.**

## 값을 치른 것 — 「번호는 변하고 내용은 안 변합니다」

안 챙겨진 규칙이 남으면 **행을 새로 만들어** 채웁니다.

그런데 **행을 끼워 넣는 순간 그 아래 번호가 전부 밀립니다.**

그러면 앞 단계에서 만든 장부의 번호가 **통째로 낡습니다.** 「3번 규칙은 7번 케이스가 담당」이라고 적어 뒀는데, **7번이 이제 8번**입니다.

처음엔 **계산해서 다시 매기려** 했습니다. **틀렸습니다.** 끼워 넣기가 여러 번 일어나고 순서도 섞이면 계산이 안 맞습니다.

지금은 **번호가 아니라 내용으로 잇습니다** — 분류 + 확인 단계 + 재현 방법을 조합해서 찾습니다.

> **위치는 변하고 내용은 안 변합니다.**

## 통과 표시를 파일로 남깁니다

넷을 다 넘으면 **완료 표시 파일을 하나 떨어뜨립니다.**

그리고 **그 파일이 없으면 이 단계를 다시 돌립니다.**

왜 기억이 아니라 파일이냐면 — **중간에 멈췄다 다시 시작할 수 있어야** 하기 때문입니다. 기억은 프로그램이 꺼지면 사라지는데, **파일은 남습니다.**

그래서 「어디까지 했더라」를 **물어볼 필요가 없습니다.** 파일이 있으면 했고, 없으면 안 한 것입니다.

## 여기부터는 자세한 기록입니다

앞 단계가 낸 수정 계획을 적용하고, 그룹 경계를 봉합한 뒤, 게이트 넷을 통과해야 다음으로 간다. 전부 코드다.

## 거부가 정상 동작이다

수정 계획에는 "이 행이 지금 이렇게 되어 있다"는 before 값이 같이 온다. 적용기는 그게 안 맞으면 **적용하지 않고 거부한다.**

거부는 고장이 아니다. **그 사이 내용이 바뀌었다는 뜻**이고, 바뀐 자리에 낡은 수정을 얹는 것보다 계획을 다시 만드는 게 맞다. 앵커가 사라졌거나 다른 수정과 충돌해도 똑같이 거부한다.

이걸 "성공률"로 보면 게이트를 느슨하게 만들고 싶어진다. 성공률이 아니라 **거부가 잡아낸 불일치 수**로 봐야 맞다.

적용 자체에는 판단이 없다. 앞 단계가 쓴 처방을 그대로 실행할 뿐이고, **처방대로 못 하겠으면 하지 않는다** — 알아서 비슷하게 고치는 경로는 아예 안 만들어 뒀다.

## 게이트 넷이 각각 다른 걸 본다

| 게이트 | 보는 것 | 걸리면 |
|---|---|---|
| 내용 | 추상 표현, 근거 없는 위임 | 수정 후 재실행 |
| 중복 | 기대 결과가 완전히 같은 행 | 병합하거나 조건 차이를 명시 |
| 추적 | 커버리지 원장의 미커버 규칙 | 행을 새로 만들어 봉합 후 재적용 |
| 그룹 | 같은 분류가 떨어져 앉음 | 자동 봉합 |

중복 게이트는 **완전 동일만 차단**하고 유사는 안 막는다. 유사는 앞 단계 판정자가 볼 몫이라서다. 코드가 유사도로 자르기 시작하면 정당하게 비슷한 케이스까지 죽는다.

## 번호는 변하고 내용은 안 변한다

미커버 규칙이 남으면 행을 새로 만들어 봉합한다. 그런데 **행을 끼워 넣는 순간 그 아래 번호가 전부 밀린다.** 앞에서 만든 커버리지 원장의 번호가 그대로 낡는다.

여기서 번호를 산술로 밀어 맞추면 안 된다. 조인은 **내용으로** 한다 — 대분류·소분류·검증 단계·기대 결과를 전부 쓴다.

소분류와 기대 결과만으로는 부족하다. 같은 기획서 안에서 앞쪽 절이 뒤쪽 절의 문장을 다시 서술하는 일이 흔해서, 둘만 쓰면 엉뚱한 행에 붙는다. 기대 결과의 부분 일치로 찾는 것도 금지다 — 다른 행에 같은 표현이 있으면 그쪽을 잡는다.

확신이 안 서면 원장을 **확정본 기준으로 다시 만드는 편**이 안전하다. 낡은 원장을 억지로 맞추는 것보다 싸다.

## 통과했다는 표시를 파일로 남긴다

넷을 다 넘으면 완료 표시 파일을 하나 떨어뜨린다. **그 파일이 없으면 이 단계를 다시 돌린다.**

이게 있어야 중간에서 재개할 수 있다. 종료 코드는 프로세스가 죽으면 같이 사라지는데, 파일은 남는다. 무인으로 도는 파이프라인에서 "여기까지는 됐다"를 아는 방법은 디스크에 적어 두는 것뿐이다.
