**코드가 한 줄도 없는 도구입니다. 파일 다섯 개에 실행되는 코드 0줄 — 실체는 «지시문 114줄 한 장»입니다. 그래서 「도구라는 게 최소 얼마나 작을 수 있나」를 보기에 제일 좋은 표본이었습니다.**

> **[도판]** 파일 다섯 개를 세는 것으로는 이 물건이 안 보인다. 지시문 한 장이 곧 제품이고, 실행 주체는 전부 호스트 에이전트다.
>
> 이 스킬의 구조. 제품 본체는 지시문 한 장이고, 그 안에 13단계 워크플로와 인도 규칙이 들어 있다. 워크플로가 만드는 후보 여섯 장은 자유 생성이 아니라 방향 셋에 변형 둘을 붙이고 좌하단과 우하단을 라벨로 미리 배정한 결과다. 다만 대표 발명 하나는 SKILL.md가 아니라 README에만 있어 실행되지 않는다.

## 이 물건이 하는 일

**회사나 서비스의 마스코트 캐릭터를 AI에게 그리게 하는 지시문**입니다.

받는 것은 이게 전부입니다.

| 파일 | 무엇 |
|---|---|
| 지시문 한 장 (114줄) | **이게 제품 전부** |
| 자랑용 그림 한 장 | 713KB — **창고 용량의 96%** |
| 나머지 셋 | 설명문 등 |

**실행 코드 0줄, 필요한 부품 0개**입니다. 그래서 「설치」는 **파일 복사**이고, 「버그 수정」은 **문장 고치기**이고, 「새 판 출시」라는 개념 자체가 없습니다.

## 제일 배울 만했던 것 — 「예쁘게」를 숫자로 적었습니다

디자인 지시는 보통 형용사로 씁니다. 「깔끔하게」 「단순하게」 같은 말입니다. 그러면 **사람마다 다르게 읽고, AI는 더 다르게 읽습니다.**

이 지시문은 **숫자로 적었습니다.**

| 무엇 | 숫자 |
|---|---|
| 겉모양을 이루는 큰 덩어리 | **4~7개** |
| 그 종(種)임을 알려 주는 특징 | **1개 이하** |
| 안쪽 색 영역 | **2개 이하** |
| 화면을 채우는 비율 | **85~95%** |

그리고 마지막에 판정 기준을 붙입니다 — **「아주 작게 줄였을 때 안 보이면, 키우거나 합치거나 지워라.」**

이게 좋은 이유는 **누가 봐도 같은 답이 나오기** 때문입니다. 「덩어리가 9개네 → 위반」은 다툴 여지가 없습니다.

## 또 하나 — 「이게 로고라고 말하지 않는다」

가장 영리했던 부분입니다.

창고 이름에 「로고」가 들어 있는데, **AI에게는 결과물을 절대 「로고」라고 부르지 않습니다.**

이유가 이렇습니다. 「로고 그려 줘」라고 하면 AI가 **로고처럼 생긴 것**을 만들려고 합니다 — 테두리를 두르고, 배경 카드를 깔고, 글자를 얹습니다. **그런 건 나중에 다 걷어내야 합니다.**

그래서 **목적을 숨기고 그림만 시킵니다.** 그러면 순수하게 캐릭터만 나옵니다.

→ **AI에게 «무엇을 만들지»를 알려 주면, 그 단어에 딸린 관습까지 같이 따라옵니다.**

## 제일 이례적이었던 것 — 「검사하지 마라」

보통은 결과물을 확인하고 안 좋으면 다시 시킵니다. 이 지시문은 그걸 **전부 금지**합니다.

| 금지된 것 |
|---|
| 결과물 검사 |
| 등급 매기기 |
| 다시 시키기 |
| 후처리로 고치기 |

나온 것을 **라벨만 붙여서 그대로** 넘깁니다.

근거 문장이 이렇습니다 — **「생성은 «제비뽑기»이지 «시험»이 아니다.」**

그리고 처음부터 이랬던 게 아닙니다. **검사 단계가 있었는데 이틀 만에 스스로 걷어냈습니다.** 해 보고 나서 내린 결정입니다.

## 그런데 제가 「핵심 발명」이라고 꼽은 것이 헛것이었습니다

여기가 이 편에서 값을 치른 자리입니다.

저는 규칙 하나를 이 물건의 핵심이라고 적었습니다 — **「캐릭터의 95~100%는 친숙한 동물이어야 한다.」**

그런데 확인해 보니 **그 규칙이 «AI가 읽는 파일»에 한 글자도 없었습니다.**

| 어디에 있나 | AI가 읽나 |
|---|---|
| 설명문(README) | **안 읽음** |
| 지시문(SKILL.md) | 읽음 — **그런데 여기엔 그 규칙이 없음** |

더 나쁜 건, 지시문 쪽은 **오히려 반대 취지**로 적혀 있었습니다. 동물·로봇·유령·식물·사물을 **동등하게** 나열하고 있었습니다.

즉 **설명문에 있고 실제 물건에 없으면, 효과는 0입니다.**

이게 이 칸에서 반복되는 교훈입니다 — **「적혀 있다」와 「돈다」는 다릅니다.** 그리고 이번엔 **어느 파일에 적혔는지**까지 봐야 했습니다.

## 나머지 기둥 하나도 무너졌습니다

제가 꼽은 또 하나는 **위의 숫자 예산**이었습니다. 그런데 변경 이력을 보니 그 숫자들이 **45시간 안에 네 번 바뀌었습니다.**

**네 번 바뀐 값은 근거가 아니라 아직 정해지지 않은 값**입니다. 인용하면 안 됩니다.

덧붙이면 — 이 창고의 커밋 29개가 **전부 45시간 안에** 몰려 있고 **그 뒤로 멈췄습니다.** 「좋아요」는 3,481개인데 **계속 지켜보는 사람은 3명**입니다.

## 그리고 기각 사유는 취향이 아니었습니다

**제 컴퓨터에 이미지 생성 도구가 0개입니다.**

확인 방법도 적어 둡니다. 제 도구 99개의 지시문 전문을 이미지 생성 관련 낱말로 훑었더니 **8건이 걸렸는데 전부 오탐**이었습니다 — 다른 단어 안에 우연히 그 글자가 들어 있었을 뿐입니다.

그래서 **설치해도 부를 곳이 없습니다.** 좋고 나쁘고 이전의 문제입니다.

## 제 것과 대 봤더니 — 셋 다 제 쪽이 이미 앞서 있었습니다

| 저쪽 기법 | 제 대응물 | 결과 |
|---|---|---|
| 숫자로 된 상한 | 제 배포 검사 장치 — 숫자 상한 **10종** + **그 숫자를 왜 그렇게 잡았는지 주석에 재유도** + 넘으면 배포 차단 | **제 쪽이 위** |
| 결과물 검사를 없앰 | 제 생성기 — 확률적 결과물에 **검사 3종**을 걸고 통과 못 하면 리포트에 못 들어감 | **방향이 정반대** |
| 질문 횟수 제한 | 제 「이해」 도구 — 질문 **최대 1개**, 명백하면 아예 안 물음 | **제 쪽이 더 강함** |

두 번째 줄이 재미있습니다. **저쪽은 검사를 없애는 게 답이라 했고, 제 쪽은 검사를 거는 게 답이었습니다.**

둘 다 맞습니다. **저쪽 결과물은 그림**이라 「맞다/틀리다」가 없고, **제 결과물은 도표**라 좌표가 어긋나면 틀린 것입니다. **결과물의 성격이 다르면 반대 처방이 둘 다 옳습니다.**

## 여기부터는 자세한 기록입니다

**코드가 한 줄도 없는 레포입니다.** 파일 5개, 실행 코드·테스트·의존성 0, 실체는 이미지 생성 에이전트에게 마스코트를 그리게 하는 지시문 114줄 한 장입니다. 그래서 「스킬이라는 물건의 최소 단위」를 보기에는 제가 뜯어본 것 중 가장 좋은 표본이었습니다. 그런데 제가 핵심 발명이라고 세운 두 기둥 중 하나는 **`README.md` 에만 있고 `SKILL.md` 에는 한 글자도 없었습니다** — 에이전트가 읽는 것은 `SKILL.md` 한 장이므로 런타임 효과가 0입니다. 나머지 하나인 숫자 예산은 45시간 안에 네 번 뒤집힌 값이었습니다. 판정은 기각이고, 사유는 취향이 아니라 **이 PC에 이미지 생성 도구가 0개라 설치해도 부를 곳이 없다**는 것입니다.

## 무엇을 하는 물건인가 — 제품이 문장 114줄뿐이다

**Agent Skills 포맷을 따르는 스킬 하나입니다.** `SKILL.md` 와 프론트매터가 전부이고, 파서도 검증기도 후처리기도 스타일 레퍼런스 이미지도 없습니다. 그래서 「설치」는 파일 복사이고 「버그 수정」은 문장 수정이며, 릴리스라는 개념 자체가 없습니다.

| 항목 | 실측 (2026-08-22) |

| 파일 | 5개 · 체크아웃 739,374 B — 그중 **96%가 쇼케이스 이미지 한 장**(713 KB, 런타임 역할 0) |
| 제품 본체 | `SKILL.md` 114줄 / 16,976 B. 13단계 워크플로 + 8줄 프롬프트 스켈레톤 |

| 판본 | 릴리스 0 · 태그 0 · CHANGELOG 0 — 사용자는 커밋 시각으로만 판본을 가른다 |

**동작 규칙은 워크플로 13단계에 다 들어 있습니다.** 주제가 없고 현재 워크스페이스가 제품 레포면 README·패키지 메타데이터·랜딩 카피를 읽기 전용으로 훑고 → 그래도 부족하면 배경 질문을 **한 라운드만** 묶어 던지고(2차 질문지는 금지) → 한 줄짜리 방향 3개를 제시한 뒤 **동의 전에는 생성하지 않습니다.** 승인이 떨어지면 방향당 변형 2개, 총 6장을 만듭니다.

프롬프트도 `Background / Subject / Complexity / Color behavior / Composition / Style / Finish / Constraints` **8줄 고정 포맷**으로 통째로 박혀 있습니다. 즉 이 레포의 정체는 **검증된 프롬프트 한 덩어리 + 그것을 언제 어떻게 쏘는지에 대한 절차서**입니다.

## 대표 기법 — 미학을 형용사가 아니라 숫자로 적는다

| 기법 | 내용 |
|---|---|
| **복잡도 예산** | 외곽 실루엣 = 큰 도형 4~7개, 종 식별 특징 ≤1, 내부 색 영역 ≤2, 캔버스 점유 85~95%. 끝에 「32×32에서 안 읽히면 키우거나 병합하거나 삭제하라」는 축소 판정을 붙입니다 |
| **3색 시맨틱 팔레트** | 색을 픽셀이 아니라 **의미 단위로** 셉니다. 명도·채도 변주는 "같은 색 패밀리 안의 부수 변동"이라 위반이 아니라고 명시합니다 |
| **코너 이머전스 + 결정론적 배정** | 캐릭터를 중앙이 아니라 좌·우 하단 모서리에서 솟게 하고, 배치를 감각이 아니라 라벨로 정합니다(A1·B1·C1 = 좌, A2·B2·C2 = 우). 홀수 배치는 남는 한 장의 불균형을 보고서에 적게 합니다 |
| **용도 은닉 프롬프트** | 레포 이름이 ip-as-logo인데도 모델에게 결과물을 `logo`·`brand mark`·`app icon` 이라 **절대 부르지 않습니다.** 목적을 알리면 모델이 카드·프레임·마스크·텍스트를 얹는 쪽으로 끌려간다는 판단입니다 |
| **제약 전달 라우팅** | 부정 제약을 모델 세대별로 다른 채널로 보냅니다 — 최신 모델은 본문 `Constraints:` 한 줄, `negative_prompt` 를 노출하는 구형은 전용 파라미터로 보내고 본문 줄은 삭제(중복 전달 금지) |
| **원패스 무검열 인도** | 가장 이례적입니다. 결과물을 검사하거나 등급을 매기거나 재시도하거나 후처리로 고치는 것을 **전부 금지**하고, 반환된 것을 라벨만 붙여 그대로 넘깁니다 |

무검열 인도의 근거 문장은 이 한 줄입니다 — *"Treat generation as a stochastic draw, not a conformance test."* 처음부터 그랬던 게 아니라 **검수 루프를 이틀 만에 스스로 걷어낸 결과**입니다.

**이 절에서 값을 치른 교훈 — 숫자를 적는 것과 숫자를 강제하는 것은 다른 일입니다.** 4~7개도 85~95%도 전부 자연어로 확률적 모델에 던지는 목표치이고, 준수를 세는 코드는 0줄입니다. 저자 본인이 절 제목을 "What it enforces"에서 **"What it guides"** 로 바꿔 강제가 아님을 인정했습니다.

## 깨본 결과 — 핵심 발명 하나가 에이전트가 읽지 않는 파일에 있었다

**「개방형 배치의 95~100%는 친숙한 동물이어야 한다」는 규칙이 `SKILL.md` 에 없습니다.** grep 결과 `animal` 은 두 곳뿐인데, 프론트매터는 동물·로봇·유령·식물·사물을 **동등하게** 나열하고 본문 18행은 *"이유 없는 동물 세 마리를 늘어놓지 말라"* 로 오히려 반대 취지입니다. `95`·`clock`·`vehicle` 은 0회. 그 규칙은 `README.md` 에만 있고, README 자신이 밝히는 대로 에이전트가 로드하는 것은 `SKILL.md` 한 장입니다. **문서에 있고 아티팩트에 없으면 런타임 효과는 0입니다.**

**「32×32에서 읽혀야 한다」는 요구는 판정 장치가 없는 게 아니라 있다가 지워졌습니다.** 이전 판본에는 11항목짜리 「비권장으로 표시할 때」 체크리스트가 있었고 그 첫 줄이 *"작은 크기에서 무너진다"* 였습니다. 한 커밋이 그 절과 재시도 루프를 통째로 삭제하고 「인도 규칙」으로 교체했습니다. 지금은 같은 파일 안에서 41행(작으면 병합하거나 삭제하라)과 113행(디테일·구도를 이유로 인도를 막지 말라)이 **서로를 무효화**합니다.

## 그리고 수확 1종마저 사라졌다 — 제 로그가 이미 답을 냈습니다

**그 진술이 거짓이었습니다.** 발행로그를 열어 보니 호마다 훅 유형이 라벨로 적혀 있고, 처음 쓰는 유형인지를 `(미사용)` 태그로 25회 표시하며, *"형식·편수 동시 변경 — 단일 변수 아님"* 같은 단일변수 규율이 명문으로 돌아가고, 상위 10개 표에서 **문형 단위로 성과를 이미 집계**하고 있었습니다. 별이 많을수록 조회가 낮게 배열되는 것을 보고 *"별을 사회적 증거로 세우는 전략은 기각한다"* 고 적어 둔 가설 기각까지 남아 있습니다. 더 나쁜 것은 제가 제안한 실험 축이 **이미 저수익으로 판정난 축**이었다는 점입니다 — 훅·형식·편수·토픽을 항목별로 맞춘 의도적 복제 2표본이 **1.8만 대 423, 43분의 1** 이었습니다.
