**Claude Code 와 Codex 는 AI 가 내 컴퓨터에서 코드를 읽고 고치게 해 주는 프로그램입니다. 두 회사가 11월 둘째 주에 낸 변경 기록을 끝까지 읽고 항목을 세어 보니, 눈에 띄는 새 기능은 전체의 한 줌이었습니다.**

## 변경 기록이 뭔가요

프로그램이 새 판을 낼 때마다 「이번에 뭘 바꿨는지」를 목록으로 적어 둡니다. 이걸 릴리스 노트라고 부릅니다. 아파트 공지문과 비슷합니다. 엘리베이터 교체 같은 큰 일은 한 줄이고, 나머지는 수십 줄의 자잘한 보수입니다.

## 세어 보니 이랬습니다

| | Claude Code v2.1.323 | Codex 0.169.0 |
|---|---|---|
| 전체 항목 | 294 | 259 |
| 새로 넣은 것 | 16 (5%) | 6 |
| 고친 것 | 154 (52%) | 6 |
| 나머지 | 변경·개선·기타 | 문서 2 · 정리 2 · 커밋 목록 243 |

**새 기능은 5%, 고친 것이 절반입니다.** 뉴스에 나오는 건 앞의 5%뿐입니다.

## 두 회사는 적는 방식부터 다릅니다

Claude Code 는 모든 줄을 한 목록에 평평하게 적습니다. Codex 는 사람이 고른 열두 줄(기능 6, 수정 6)을 위에 두고 그 아래에 커밋 243개를 붙입니다.

그래서 «항목 수»로 누가 더 부지런한지 비교하면 틀립니다. **센 기준이 서로 다른 자로 잰 겁니다.**

## 제 첫 요약이 놓친 것

처음엔 두 회사 레포에서 최근 릴리스의 앞부분 700자씩만 가져와 요약했습니다. v2.1.323 은 전문이 41,650바이트라 **전체의 1.7%** 만 본 셈입니다. 새 기능은 맨 앞에 있어서 잘 잡혔습니다. 샌드박스 구멍을 막은 줄들은 중간에 있어서 통째로 빠져 있었습니다.

## 여기부터는 자세한 기록입니다

릴리스 노트는 맨 앞이 가장 읽기 쉽고 가장 덜 대표적입니다. 이 편은 2026-11-14 에 공개 저장소에서 받은 노트 전문을 줄 단위로 센 기록이고, 어느 쪽이 더 낫다는 판정은 하지 않습니다.

## 무엇을 어떻게 셌나

받은 것은 세 장입니다. Claude Code v2.1.323(11-12), v2.1.325(11-13), Codex rust-v0.169.0(11-13)입니다. 각 장에서 `- ` 로 시작하는 줄을 한 항목으로 쳤습니다.

Claude Code 쪽은 줄 첫 단어로 갈랐습니다. `Added` 로 시작하면 추가, `Fixed` 면 수정, `Changed`·`Improved`·`Renamed`·`Removed`·`Deprecated` 는 변경으로 묶었습니다. 이 분류는 문장을 읽은 판단이 아니라 **첫 단어 일치**입니다.

| Claude Code | 전체 | 추가 | 수정 | 변경 | 그 밖 |
|---|---|---|---|---|---|
| v2.1.323 | 294 | 16 | 154 | 62 | 62 |
| v2.1.325 | 139 | 3 | 79 | 40 | 17 |

수정 비중은 52%와 57%입니다. 둘 다 절반을 넘었다는 것까지만 말할 수 있고, 두 장으로 «보통 이렇다»를 말하기엔 표본이 작습니다.

Codex 0.169.0 은 구조가 다릅니다. New Features 6, Bug Fixes 6, Documentation 2, Chores 2, 그리고 Changelog 243줄이 따로 붙어 있습니다. 앞의 열여섯 줄만 사람이 쓴 문장이고 뒤의 243줄은 커밋 제목입니다. 그래서 «추가 6»은 비교 가능한 수가 아닙니다.

## 이번 주에 실제로 있던 일

항목 수가 아니라 내용으로 보면 눈에 띄는 쪽이 둘이었습니다.

**샌드박스를 다루는 줄이 많았습니다.** `sandbox` 라는 단어가 v2.1.323 에 14번, v2.1.325 에 11번 나옵니다. 키워드 일치라서 전부가 보안 수정은 아닙니다. 다만 v2.1.325 첫머리에는 zstd 로 압축된 응답을 푸는 방식의 보안 문제를 고쳤다는 줄이 있고, 격리된 작업 폴더에서 보호 파일(`.claude` 등)을 못 건드릴 때 Claude 에게 알려 주는 줄도 있습니다.

**확장 구조를 정리했습니다.** v2.1.323 은 플러그인이 `engines["claude-code"]` 로 지원하는 Claude Code 버전 범위를 적게 했고, 범위 밖이면 설치·갱신·로드를 막습니다. 같은 판에 Claude 가 도구를 직접 부르는 대신 JavaScript 를 써서 부르는 실험 기능 **Code Mode** 가 옵트인으로 들어왔습니다.

Codex 0.169.0 쪽은 터미널 화면에 관한 기능이 앞에 섭니다. 옆 대화 탭 여러 개, 지난 작업 검색, 끝난 활동을 접어 두는 보기, 터미널에서 모델 제공자를 추가하는 기능, 클라우드 대화를 터미널에서 다루는 기능입니다.

## SDK 쪽도 잠깐

개발자용 파이썬 SDK 는 11월에 Anthropic 이 v2.5~2.8, OpenAI 가 v3.48~3.51 까지 나왔습니다. Anthropic 쪽 수정은 Bedrock·Vertex 같은 클라우드 경로에 빈 값이나 `.` `..` 가 들어가는 것을 막는 줄이 많았고, OpenAI 쪽은 타입이 붙은 비동기 함수 도구와 에이전트 세션 옵션이 들어왔습니다. 이 둘은 릴리스 제목과 앞부분만 읽었습니다.

## 값을 치르고 배운 것

**앞부분만 읽은 요약은 «새 기능 위주»로 기운다.** 릴리스 노트는 새 기능을 맨 위에 두는 문서라, 앞 700자는 구조상 가장 새 것에 가깝습니다. 전문을 세어 보고서야 첫 요약이 수정 줄의 절반을 못 본 채 쓴 것임을 알았습니다.

**항목 수는 활동량이 아니라 적는 습관이다.** 294 대 259 를 보고 두 회사의 작업량을 말할 수는 없습니다. 한쪽은 평평한 목록이고 다른 쪽은 큐레이션 열두 줄에 커밋 목록입니다.

## 못 한 것

- 줄을 하나씩 읽고 분류하지 않았다. 첫 단어 일치와 키워드 개수가 전부이고, `sandbox` 14회가 보안 수정 14건이라는 뜻은 아니다.
- 릴리스 두 장과 한 장이 표본의 전부다. «Claude Code 는 수정이 절반»이라는 일반화는 못 한다.
- Codex 의 커밋 243줄은 세기만 했고 내용은 분류하지 않았다.
- 0.171.0 알파 릴리스는 본문이 제목뿐이라 볼 것이 없었다.
- 모델 성능이나 실제 체감 속도는 이 글의 범위 밖이다. 변경 기록이 말해 주지 않는다.
- 소스 diff 는 열지 않았다. 노트가 «고쳤다»고 적은 것을 코드로 확인한 것은 없다.

## 판정

**도입할 것이 없는 편입니다.** 두 도구는 이미 쓰고 있습니다. 이 편이 남기는 건 읽는 법 하나입니다. 릴리스 노트를 볼 때는 앞부분의 새 기능 말고 **중간의 «Fixed» 줄 중 격리·권한·토큰이 들어간 것**을 따로 훑습니다. 새 기능은 쓰다 보면 알게 되지만, 막힌 구멍은 알려 주지 않으면 모르기 때문입니다.
