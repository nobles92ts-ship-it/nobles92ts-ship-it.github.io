# 스킬 하나로 광고 이미지 · 종량제 라우팅

**도구 하나로 광고 이미지를 만들고, 그걸 영상으로 만들고, 거기서 색을 뽑아 웹페이지까지 짜는 7분짜리 시연입니다. 도구 설계는 잘 만든 실물입니다. 그런데 제목이 내건 결론이 «영상 자신이 띄운 표»에서 무너집니다.**

> **[도판]** 모델 목록이 아니라 「예산 판정이 어느 칸에 있는가」가 이 설계의 핵심이다.
>
> 스킬은 오케스트레이션 문서 하나와 모델별 레시피 파일들로 나뉜다. 전체 절차와 모델 기준은 위쪽에 두고 실제 호출법은 모델 파일에 내려둔다. 실행은 요청 파싱, 컷 기획, 라우팅과 예산 계산, 프롬프트 작성과 생성, 정리의 다섯 단계고 예산 초과 판정이 호출 전에 들어간다.

## 시연 내용 — 한 줄 시키면 끝까지 갑니다

사람이 하는 일은 **「광고 이미지 만들어 줘」 한 줄**입니다. 그 뒤로는 이렇게 흘러갑니다.

1. 이미지 6종을 만듦
2. 그중 하나를 골라 영상으로 만듦
3. **그 이미지에서 색을 뽑아** 웹페이지를 코딩

마지막이 좋습니다. 색을 **사람이 정해 주는 게 아니라 결과물에서 추출**합니다. 그래서 이미지와 페이지의 분위기가 자동으로 맞습니다.

비용은 1단계 $0.73, 2단계 약 $1.16이었습니다.

## 잘 만든 설계 — 「예산 판정이 어느 칸에 있는가」

이 도구에서 제일 배울 만한 부분입니다.

돈이 나가는 작업을 AI에게 시킬 때, **예산 확인을 «호출한 뒤»에 하면 늦습니다.** 이미 나갔으니까요.

이 도구는 **호출 «전»에** 단가 × 장수를 더해서 **넘치는지 먼저 계산**합니다. 넘치면 **장수를 줄이거나 싼 모델로 바꿉니다.**

| 언제 확인하나 | 결과 |
|---|---|
| 호출한 뒤 | **이미 나간 돈** |
| **호출하기 전** | **안 나가게 막을 수 있음** |

## 또 하나 — 「제일 흔한 오해를 도구가 미리 막습니다」

작은데 좋은 설계입니다.

잔액이 0일 때 나오는 오류 코드가, **비밀번호가 틀렸을 때 나오는 것과 같습니다.** 그래서 사람들이 **「키가 잘못됐나」 하고 엉뚱한 데를 몇 시간 헤맵니다.**

이 도구는 그 오류가 나면 <strong>「키 문제가 아니라 잔액 문제입니다」</strong>라고 안내합니다.

**제일 흔한 오진을 도구가 미리 차단**한 것입니다.

## 그리고 제가 실제로 가져온 것 — 「품질 기준을 한 단어로」

가져온 건 하나입니다. 그리고 비용이 0이라 바로 넣었습니다.

AI에게 품질을 요구할 때 **「잘 만들어 줘」는 아무 효과가 없습니다.** 대신 이렇게 씁니다.

| 대신 쓰는 말 |
|---|
| **「쇼케이스 작품으로 취급해」** |
| **「그라데이션으로 예술인 척하지 말고 진짜 이미지를 써」** |
| **「색은 결과물에서 뽑아」** |

두 번째가 특히 좋습니다. **AI가 성의 없이 때울 때 쓰는 흔한 수법을 이름으로 지목**했습니다. 「잘 해 줘」보다 <strong>「이 수법을 쓰지 마」</strong>가 훨씬 강합니다.

## 그런데 제목의 전제가 영상 자신의 표로 반박됩니다

이 편의 본론입니다.

영상 제목이 <strong>「구독 해지했습니다」</strong>입니다. 즉 **정액 구독보다 쓴 만큼 내는 쪽이 싸다**는 주장입니다.

그런데 영상이 **자기가 띄운 비교 표**에서, **영상 생성 쪽은 구독이 종량제 세 곳보다 전부 쌌습니다.**

그리고 발표자도 **말미에 그걸 인정**합니다.

즉 **제목은 「구독 해지」인데, 영상 안에 「구독이 나은 경우」가 들어 있습니다.**

## 그리고 더 무거운 게 하나 더 있습니다

이 영상의 **출발 동기**가 특정 서비스의 이용 약관 문제였습니다.

**자기가 화면에 띄운 약관 원문이 정반대 내용**이었습니다.

즉 **띄워 놓고 안 읽은 것**입니다. 그리고 그게 **영상 전체의 출발점**이었습니다.

→ 배운 것: **화면에 근거를 띄웠다는 것과, 그 근거가 주장을 뒷받침한다는 것은 다릅니다.** 띄운 것을 읽는 사람은 의외로 적습니다.

## 재현성을 먼저 적어 둡니다

이 영상의 한계도 같이 적습니다.

| 항목 | 상태 |
|---|---|
| 비용 실측 | **5곳 중 1곳만 실제 청구서 확인.** 나머지는 공개 가격표 계산 |
| 도구 코드 | **공개 창고에 없음** — 조건부 공유 |

두 번째 때문에 **따라 해 볼 수가 없습니다.** 그래서 이 편의 서술은 **화면에서 본 데까지**입니다.

## 나머지 판정

| 무엇 | 판정 | 왜 |
|---|---|---|
| 이미지 → 영상 → 색 추출로 통일 | **보류** | 다시 볼 조건 = **배포 결정이 난 뒤** |
| 종량제 이미지 API 도입 | **보류** | 다시 볼 조건 = **에셋을 실제로 대량 생성할 때.** ⚠ 최저가 한 곳은 **약관 문제가 풀리기 전엔 후보 제외** |
| 예산 상한 + 재시도 | **기각** | 제 쪽은 정액제라 비용 압박이 없고, 재시도는 **이미 다른 장치가 담당** |

그리고 **이미 하고 있던 둘**은 수확에서 뺐습니다 — 제 영상 분석 도구는 이미 종량제를 쓰고 있었고, 설명문에 호출 조건을 나열하는 관행도 이미 여러 도구에 적용돼 있었습니다.

**「새로 배운 것」을 셀 때 이미 하던 것을 빼지 않으면 숫자가 부풀려집니다.**

## 여기부터는 자세한 기록입니다

**스킬 설계 자체는 잘 만든 실물입니다** — 제공자 라우팅 + 예산 상한 + 결과물 체이닝이 절차에 박혀 있고, 사용자는 이미지 프롬프트를 한 줄도 쓰지 않습니다. **문제는 제목입니다.** *"구독 해지했습니다"* 의 근거가 **영상 자신이 띄운 표에서 무너집니다** — 영상 생성에서는 구독이 종량제 세 곳보다 전부 쌉니다. 발표자도 말미에 인정합니다. 그리고 더 무거운 게 하나 더 있습니다. **이 영상의 출발 동기인 약관 이슈가, 자기가 화면에 띄운 원문과 정반대입니다.** 가져올 것은 비용 결론이 아니라 **프롬프트 설계 기법 1종**입니다.



## 무엇을 하는 물건인가

**스킬 하나로 광고 이미지 여러 장을 만들고, 그중 하나를 영상으로 만들고, 그 이미지에서 색을 뽑아 원페이지 사이트까지 코딩하는 체인**을 보여주는 7분짜리 튜토리얼입니다. 그 뒤에 붙는 생성 API를 **구독형 대신 종량제 세 곳으로 라우팅**하는 게 주장입니다.

**사용자는 이미지 프롬프트를 한 줄도 안 씁니다.** *"무엇을(제품) + 기준(참고 이미지) + 제약(규칙)"* 만 주면 **컨셉 기획·모델 선택·프롬프트 작성·API 호출을 전부 스킬이 합니다.**

| 항목 | 값 |
|---|---|
| 1단계 이미지 6종 | **$0.73** / 예산 $2 |
| 2단계 사이트 + 영상 | **~$1.16** / 예산 $2 |
| 최종 산출물 | 1.1MB 단일 HTML · 5초 음소거 루프 풀스크린 배경 |
| 실측 범위 | ⚠ 5개 플랫폼 중 **1곳만 실제 청구서 확인**. 나머지는 공개 가격표 계산 |
| 재현성 | ⚠ **낮음.** 스킬 코드가 공개 저장소에 없고 조건부 공유입니다 |

## 대표 설계 결정

| 이름 | 내용 |
|---|---|
| **설명문에 트리거 단어 다발** | 평소엔 설명문만 보고 있다가 요청이 맞아떨어지면 본문 전체를 읽습니다. 그래서 **설명문에 트리거 단어를 잔뜩 넣는 것**이 요령 |
| **절차와 호출법을 분리** | 위쪽 문서엔 전체 절차와 모델 선택 기준만, **실제 호출법은 모델별 파일에** 내려둡니다. 새 모델은 템플릿 복사 |
| **예산이 절차에 박혀 있다** | 호출 전에 단가 × 장수를 합산해 초과 여부를 **미리** 계산합니다. 넘치면 장수를 줄이거나 싼 모델로 |
| 키 탐색 순서 + 금지 | 환경변수 → 폴더 파일 → 사용자에게 요청. **키를 스킬 파일에 절대 저장 금지**(공유물이니까) |
| **오진을 미리 차단** | 잔액 0에서 나는 403을 **"키 오류가 아니라 잔액 문제"** 라고 안내합니다. 가장 흔한 오진을 스킬이 막습니다 |
| **품질 기준을 한 단어로** | *"쇼케이스 작품으로 취급해"* · *"그라데이션으로 아트인 척하지 말고 진짜 이미지를 써"* · **색은 결과 이미지에서 뽑게** |

## 깨본 결과 — 넷

**❶ 제목의 전제가 영상 자신의 표로 반박됩니다.**

> **[도판]** 같은 발표 안에서 표 두 장이 반대 방향을 가리킨다. 제목은 앞의 한 장만 읽은 결과다.
>
> 영상이 만든 두 개의 비용표를 나란히 보면 결론이 뒤집힌다. 이미지 한 장당에서는 종량제 한 곳이 구독보다 여섯 배 싸지만, 영상 한 편당에서는 구독이 종량제 세 곳보다 전부 싸다. 그리고 가장 싼 종량제 값은 발표자 본인이 못 믿겠다고 유보를 단 값이다.

**❷ 가장 무거운 반증 — 출발 동기가 자기가 띄운 근거와 어긋납니다.** 나레이션은 *"비공개 콘텐츠도 AI 학습에 사용될 수 있다"* 고 말하는데, **화면에 띄운 공식 게시글 원문에는 정확히 그 반대**가 적혀 있습니다. 비공개는 비공개로 남고 공개 페이지에 올린 것만 쓴다는 취지입니다. **이 영상이 출발한 이유 자체가 자기 화면과 상충합니다.**

**❸ 가장 싼 값은 발표자 본인이 못 믿는 값입니다.** *"API를 타지 않고 실제로 구독한 모델을 타는 것 같다. 더 알아보고 공유드리겠다."* ⚠ 이 유보는 가볍지 않습니다 — 사실이라면 **제공자 약관 위반 위험이 가격에 숨어 있다**는 뜻입니다. 여기에 본인이 인정한 *"서버가 불안정하다"* 가 겹칩니다.

**❹ 실측 1건, 나머지 넷은 가격표 계산입니다.** 하필 **가장 결정적인 값이 실측이 아닙니다.**

## 내 환경에 대봤다

**먼저 이미 해결된 것부터 지웠습니다.** 제 [영상 분석 도구](/ko/built/watch/index.md)는 이미 종량제 전사 API를 쓰고 있고, 설명문에 트리거 단어를 나열하는 관행도 이미 여러 스킬에 적용돼 있습니다. **이 영상이 새로 가르쳐 주는 것에서 이 둘은 빠집니다.**

| 기법 | 적용처 | 판정 |
|---|---|---|
| **품질 기준을 한 단어로 선언** | 영상 분석 도구의 리포트 생성 지시 · 글쓰기 프롬프트 | **채택 — 비용 0, 즉시** |
| 이미지 → 영상 배경 + 색 추출로 세계관 통일 | 이 사이트의 랜딩 / 게임 소개 페이지 | **보류.** 재개 = **도메인·배포 결정 후** |
| 종량제 이미지·영상 API 도입 | [게임 에셋 생성](/ko/built/moon-studio/index.md) | **보류.** 재개 = 에셋을 실제로 대량 생성하는 단계. ⚠ 최저가 한 곳은 약관 유보가 풀리기 전엔 후보 제외 |
| 예산 상한 + 재시도 1회 | — | **기각.** 정액제라 비용 압박이 없고, 재시도는 이미 파이프라인 게이트가 담당 |
| 모델별 레시피 + 템플릿 | — | **기각.** 라우팅할 다중 제공자가 애초에 없습니다 |
| 갤러리 + 지출 기록 파일 | — | **기각.** 라이브러리 등재 체계와 런 폴더 규약이 같은 일을 합니다 |

## 판정

**채택은 1건인데, 그 1건도 아직 추정입니다.**

⚠ **이 영상에는 대조군이 없습니다.** *"쇼케이스"* 만 빼고 돌린 비교를 안 보여줍니다. 결과물이 좋은 건 사실이지만 그게 **그 단어 덕인지, 참고 이미지 4장 덕인지, 모델 성능 덕인지 분리되지 않았습니다.** 그래서 이 채택은 `[추정]` 상태이고 **표본이 1이라 신뢰구간을 낼 수 없습니다.**

**실측으로 승격시키는 방법까지 적어 뒀습니다** — 앞으로 만드는 리포트 중 **10%를 무처리로 남겨**(품질 선언 문장 없이) 결과를 비교합니다. 그때 `[실측]`이 됩니다.

**그리고 이 분석의 가장 약한 고리를 적어 둡니다.** ⚠ **스킬 코드 원본을 못 봤습니다.** 모든 구조 설명은 발표자의 화면을 프레임에서 읽어 재구성한 것이고, **실제 파일이 화면대로 동작하는지는 검증하지 않았습니다.** 위 판정은 *"이 설계도가 좋은가"* 에 대한 것이지 *"이 구현이 동작하는가"* 에 대한 것이 아닙니다.

**못 한 것 셋** — ① 약관 원문을 직접 대조하지 않았습니다(띄운 캡처를 읽었을 뿐입니다). 이 반증을 인용할 일이 생기면 **원문부터 확인해야 합니다.** ② 최저가 제공자가 실제로 무엇을 타는지는 확인 불가입니다. ③ ⚠ **가격표 다섯 종은 스냅샷입니다.** 이미지 생성 API 가격은 분기 단위로 바뀌니 **도입 시점에 재확인 없이 인용하면 안 됩니다.**

**이 편에서 값을 치른 교훈은 「같은 발표 안에서 표를 끝까지 읽어라」입니다.** 앞의 표만 보면 제목이 맞고 뒤의 표까지 보면 틀립니다. 발표자가 정직하게 말미에 인정하는데도, **제목과 썸네일은 앞의 표로 만들어져 있습니다.**

그리고 ⚠ **좋은 설계와 좋은 결론은 별개입니다.** 스킬 구조는 가져올 게 있는 실물인데 비용 결론은 못 씁니다. **이 둘을 한 덩어리로 받으면 설계를 얻는 대가로 틀린 결론까지 같이 들여옵니다.**
